# Capability registration

**Registration status:** proposed / approved for stated scope / suspended / retired.

| Field | Definition to complete |
|---|---|
| Capability ID, name, and purpose | Stable identity and business reason |
| Business, technical, data, and operations owners | Accountable roles |
| Supported contract and version | Input/output schemas, safe errors, compatibility rules |
| Server and artifact identity | Reviewed deployment reference and integrity evidence |
| Protocol, transport, SDK, and extension compatibility | Tested combinations |
| Reachable systems and execution permissions | Actual authority, including indirect actions |
| Data classifications and allowed output fields | Scope and minimization |
| Permitted workloads, users, tenants, and objects | Authorization boundaries |
| Identity and delegation model | Trusted issuer, audience, scope, and revocation approach |
| Action classification and consequence tier | Read, change, reversal, materiality, safety impact |
| Business policy and enforcement locations | Rules, versions, decision and enforcement owners |
| Human approval rule | Authority, transaction binding, expiry, substitution and replay controls |
| Transaction semantics | State validation, aggregate limits, concurrency, atomicity |
| Idempotency and uncertain outcome handling | Key scope, replay behavior, reconciliation |
| Rate, budget, and capacity limits | Per subject, tenant, and service |
| Evidence contract | Fields, protection, access, retention, deletion |
| Evaluation and security evidence | Required tests and controlled evidence references |
| Support and recovery objectives | Monitoring, incident owner, fallback, repair |
| Change and retirement plan | Notice period, consumer inventory, review and retirement triggers |
| Exceptions and residual risks | Named acceptance authority and expiry |

Do not publish completed internal inventories. Use synthetic endpoints and references for public examples.
